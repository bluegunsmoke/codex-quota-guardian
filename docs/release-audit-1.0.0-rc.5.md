# Codex Guardian 1.0.0-rc.5 发布候选审计（已由 rc.6 取代）

审计日期：2026-07-14  
范围：`outputs/Codex_Guardian_完整开发流程单.md` Phase 0–8、测试总流程和发布门禁。实机证明包上下文会虚拟化新建 AppData 文件，即使代码使用绝对路径；rc.6 将安装与数据迁到用户配置目录的非 AppData 子目录。本文件保留为审计轨迹，不作为交付结论。  
判定：自动化与可重复桌面门禁全部通过后交给维护者本机测试；维护者明确确认前不发布、推送、打标签或创建 Release。

## 候选修正轨迹

- rc.3 的 Windows App SDK 构建暴露了应用包 `LocalCache` 与普通构建数据目录不一致的问题。
- rc.4 尝试优先使用进程 `LOCALAPPDATA`，实机证明该变量也被包身份重定向，因此未交付。
- rc.5 显式识别 `...\Packages\<包>\LocalCache\Local` 并还原真实 LocalAppData 根，同时保留企业重定向到其他磁盘的普通路径。稳定路径缺文件时只从旧位置复制，不删除旧文件。
- 设置、窗口状态、额度历史和通知决策的目标目录统一为 `%LOCALAPPDATA%\CodexGuardian`。

## 逐阶段结论

| 阶段 | 结论 | 主要证据 |
|---|---|---|
| Phase 0 数据源 | 自动通过；额度一致性本机复核 | 只读本地 `rate_limits`、Provider 契约、fail-closed 测试、真实诊断 CLI、无网络 API 扫描 |

| Phase 4 Advisor/通知 | 自动与降级桌面通道通过；原生系统操作本机复核 | 一分钟规则、四级决策、去重/冷却/恶化/静默、操作参数解析和决策日志测试 |
| Phase 5 Timeline | 自动与桌面通过 | 场景、缩放、键盘游标、重置/保留线、不确定性与无置信曲线测试 |
| Phase 6 个性化 | 自动与桌面通过 | 策略、任务预算、周报测试；关闭个性化后实时额度和时间线保留 |
